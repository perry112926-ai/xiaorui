# Personal agent 能力检查与改进

日期：2026-11-06。检查的是实际代码与可执行行为，不凭采用 nanobot 或拥有记忆数据库就判定“优秀 personal agent”。

| --- | --- | --- |

## 复现的问题与修改

1. **否定和讨论被当成删除授权。** 原来只要包含“忘记／delete”就清空整个推断库。新增直接肯定请求识别，阻止“不要忘记”和“为什么会忘记”产生删除；删除订单、购物车等命令不进入记忆删除分支。
2. **删除一个主题影响其他偏好。** 推断库按主题匹配删除；宿主删除推断主题后只轮换当前用户的模型上下文，防止 SDK 原历史重新召回。删除显式普通资料时也按该字段的已知旧值精确清理原话，避免字段名未出现在原话中而漏删；旧值 all 不作为全删命令。若 forget_epoch 改变，只迁移该 owner 已过滤的剩余推断记忆；其他 owner 不迁移。重要确认资料的原有权限不变。
3. **长期决定被当成临时要求。** 不再因为出现“今天”就一概跳过；“今天决定以后……”可进入整理。明确临时或禁止保存的内容仍不归档。
4. **偏好已自动落盘，回答却要求用户再说“请记住”。** 明确区分自动偏好库与手动资料工具，拒绝未授权手动写入时返回可面向用户的说明，不把内部上下文名字直接播报。
5. **只有用户原话可独立检索。** 归档现在可同时保存成功回复并标明 user／assistant；偏好提取仍只以用户原话为证据，不能把助手建议当成用户事实。
6. **长消息只留前2,000字。** 改为按问题寻找相关窗口，并保留原文开头的日期和说话者。检索结果按实际记录顺序组织，帮助处理更新和时间关系。
7. **记忆 JSON 被上下文截断。** 按实际 JSON 和方括号转义后的长度计费，偏好单独限额、完整块留出宿主边界余量。首版预算过紧导致全量测评分数回退，保留中间结果并继续修正。
8. **记忆故障污染业务状态。** 已完成的回答／执行不再因为记忆 SQLite 或文件故障被标为任务失败；trace 记录 `memory.learn=unavailable`，避免诱发重复操作。

主题删除仍是词法匹配，没有完整的语义主题树或删除墓碑。同一条原话中包含多个主题时，可能保守删除整条原话。另加持久的任务召回屏障，遗忘前的任务正文不能经 task_records 再带回已删信息，执行状态及原始审计记录保留。普通资料删除仍可能使其他浏览器会话失效；这不是跨库物理擦除全部审计数据。完整应用验收和公开 reader 评测应分开解释。

## 公开评测协议

- [LongMemEval 官方仓库](https://github.com/xiaowu0162/LongMemEval)：使用 S 版完整500题进行检索和问答；另用 oracle 的500题检索、120题固定分层问答诊断“拿到证据后的阅读能力”。**oracle 分数不当作 S 分数。**
- 数据由官方公开数据集的镜像获得，记录 SHA-256。索引仅使用角色、原话、原始时间；`has_answer`、问题、答案和证据会话标签均不进入索引。评分时才读取 gold。
- LongMemEval 裁判提示取自官方 `get_anscheck_prompt`，包括更新、时间、偏好及 abstention 规则；通过 AST 只加载该纯函数，不运行上游脚本主体。裁判与 reader 使用本机已配置的同一方舟模型，**没有使用官方默认 GPT-4o 裁判，不能直接比较官方榜单**。
- [LoCoMo 官方仓库](https://github.com/snap-research/locomo)：全部1,982条带证据标注的问题测检索。问答选择类别1–4各25题，共100题，按 sample_id + 问题索引的 SHA-256 排序选择；答案不参与选题。类别5不混入问答正确率。
- LoCoMo 使用独立的同模型 PASS／FAIL 诊断裁判，没有宣称官方 F1／榜单 accuracy。
- 所有公开测试都是**直接加载原始对话到生产记忆表，再运行生产 recall 和独立 reader**。没有逐轮调用完整 AgentService 或自动 curator；这些分数不证明写入选择、主动性、工具规划及真人体验。
- 真实应用另用九轮虚构对话验证；每轮重新构造 AgentService，工具边界强制只放行本地资料和任务工具，所有外部服务工具均被阻断。
- 前后固定模型、reader 提示、问题集合及评分协议。保留基线、首版回退和最终输出。测试集用于诊断和改进，不声称仍是未见保留集；单次模型裁判仍有误差，微小分差不能解读为统计显著。

结果见 [results.md](results.md)。未运行的公开套件不记作通过，也没有把项目自己的功能测试称为公开 benchmark。

```sh
.venv/bin/python -m experiments.longmemeval_eval /path/to/longmemeval_s_cleaned.json \
  --judge-source /path/to/upstream/evaluate_qa.py --per-category 500 --output /tmp/lme.json
.venv/bin/python -m experiments.agent_public_eval /path/to/locomo10.json --output /tmp/locomo.json
.venv/bin/python -m experiments.companion_memory_bench /path/to/locomo10.json --k 32
.venv/bin/python -m experiments.agent_capability_probe --output /tmp/application.json
.venv/bin/python -m unittest discover -s tests -q
```

前后生产记忆源码、数据、reader 和上游裁判提示的哈希保存在报告中。原始数据集、密钥和本地用户数据均不提交。

下一阶段应优先补语义召回／问题分解与独立保留集验证，再接入 MemoryArena 的记忆到行动测试、PersonaMem 的个性化测试，以及模拟环境中的 τ²-bench 和 AgentDojo。长期目标与通知应作为独立完整功能实现，不能通过增加几个工具名或打开 Cron 开关就判定具备。
