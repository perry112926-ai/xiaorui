# 小瑞产品与系统设计

小瑞是面向老年人的中文个人生活助手。家人可以先协助配置，老人日常像联系一个熟悉的人一样，用自己的话安排出门、用餐等事务。小瑞听懂需求、查真实信息、把选项讲清楚，由老人决定下一步。交付形态是在 Mac 上启动的本地服务和浏览器界面。

## 1. 用户与设计目标

老人可能很清楚自己想去哪、想吃什么，却需要在多个应用之间切换，填写地址、找门店、辨认规格、核对费用。小瑞把这些步骤收进同一个持续对话。老人可以分几句话表达，可以停下来想、改口、拒绝或结束。家人主要协助核对本人资料、家庭住址、常用联系人和服务配置。日常选择与消费确认由老人掌握。

语言像成年人之间交流，默认一两句，每次只问眼下必要的一件事。知道预算或口味就承接，缺信息再补问。对话内可以主动问“您想外送还是自己取？”，也可以在对方看不清时把选项念出来。定时问候、提醒和兴趣分享属于后续能力，需要用户设置可接受的时间、频率和暂停方式。[产品理念](product-identity.md)

## 2. 同一个联系人，两种交流方式

| 场景 | 交互规则 |
| --- | --- |
| 发消息 | 保留原版底部输入框，可发文字、单条语音和图片。短消息的气泡随内容收窄，长内容到达宽度上限后换行。送达、查询和生成中的反馈跟随对应消息，最终回复在原位置接续。 |
| 打电话 | 从加号进入，接通问候一次。顶部灵动岛显示通话中、时长和挂断，听取或处理状态放在岛下小字里。通话中底部输入框照常可用，手动发送的内容仍按普通消息展示和回复。 |
| 通话中发卡片 | 小瑞说“我给您发了几份套餐，选好告诉我”。卡片留在聊天里，口头报选项或点击有效卡片都能继续。看不清时可请小瑞念出价格和选项。 |
| 结束通话 | 挂断停止收音和播报。口头问答和实时转录留在通话交互范围内，聊天里只记一条“语音通话＋时长”，另保留业务卡片和手动消息。刷新后可看到摘要，由用户决定是否再次拨打。 |

等待时，聊天进度归对应消息，通话进度归顶部灵动岛。桌面侧边角色用倾听、思考、说话、餐饮或出行姿态辅助辨认，以收音、真实播报和任务进度驱动。窄屏优先保留输入和卡片，系统开启减少动态时用静态姿态表达状态。[交互设计](interaction-design.md) · [电话交互](phone-interaction.md) · [角色状态](companion-states.md)

## 3. 典型流程：打电话点午饭

1. 老人拨通后说“帮我点个午饭”，停一会儿又说“送到家，三十块以内”。小瑞简短说明当前可以帮忙点麦当劳，承接预算和配送需求，缺必要信息时一次补问一项。
2. 小瑞用本轮核对的地址查配送范围和可售餐品，发少量带图片和价格的候选，并在电话里说清楚卡片怎么选。老人可以说“第二份”，也可以点击，或请小瑞念一下。
3. 选完后展示确认卡片，读出餐品、地址和含费总额。老人改成自取或换餐时，小瑞更新方案，之前的确认失效。正式提交前重新核价，实质变化时请老人重新核对确认。
4. 收到明确确认后，由宿主执行开关允许的操作。若收到官方待支付回执，展示支付入口和实际状态，由用户完成支付。若结果未知，先查订单再处理。挂断、停止播报、放弃待确认方案和取消已创建订单是不同操作。

这条流程也适用于出行中的地点、车型和金额核对。平台返回的地图、菜单参考价、实际核价和订单状态分别展示，方便用户知道自己正在选择、确认还是等待结果。[服务范围与异常处理](services.md)

## 4. 资料、记忆与隐私

“我的资料卡”保存本人或家人核对过的重要信息。家庭住址、电话和联系人经人工确认后成为权威数据。聊天里提到的普通偏好可以形成带来源的记忆，也可以纠正或忘记。长期偏好与本轮条件分开处理，例如“今天预算三十元”只用于当前任务。资料变动使相关旧方案失效，已执行操作继续按实际记录核查。

资料、模型召回、页面历史和交易回执分开存储。页面只展示通话摘要，底层处理记录仍可能保留转录。服务在本机运行，语音、模型和生活服务查询需要网络，任务所需的资料可能传给对应服务。主题遗忘影响后续召回，页面历史、云端处理和备份各有保留范围。[记忆与隔离](memory.md) · [部署与数据边界](setup.md)

## 5. 系统分工与执行边界

React 页面负责聊天、通话、卡片和人工确认，FastAPI 宿主负责消息收件箱、进度、资料和交易状态。nanobot 运行模型和工具循环，使用已注册的工具理解需求、提出建议和查询。正式电话通过 ASR 将语音转为文字、交给同一 Agent，再由 TTS 播放回复。文字和电话可共享当前办事上下文，消息展示、语音播放和进度各自归属。SQLite 与本机文件持久化记录，SSE 将消息和进度发回页面。

服务接入覆盖高德地点、路线和天气，麦当劳餐饮，瑞幸饮品，滴滴出行及飞猪机票查询。用户选择后，由宿主核对方案归属、版本、有效期和明确确认，再核价和执行。超时后标记待核查，重启恢复记录，外部写入结果未知时先查询。用户可沿官方入口付款、预订或处理超出小瑞范围的业务。[系统架构](../ARCHITECTURE.md) · [服务边界](services.md)

## 6. 验收与交付

| 验收层 | 检查什么 |
| --- | --- |
| 自动化与构建 | 短消息气泡、并行文字与通话、进度归属、旧卡片失效、重复确认、挂断与重启恢复。前端改动同时检查生产构建。 |
| 真实服务 | 用官方接口核对实际查询、卡片和核价。待支付、已付款和履约完成分别取证，任何真实写入或消费须事先获得具体授权。 |
| 老人实机试用 | 让老人自己完成连续语音问答、看卡或听卡、改口、确认与退出。覆盖说话中停顿、插话、方言、回声、弱网和拒绝麦克风权限，观察能否理解状态并自主继续。 |
| 本地交付 | 在干净 Mac 上从仓库安装、配置凭据并运行启动器，按同一演示路径验证实际服务，检查交付包与文档使用虚构示例。 |

当前版本已有持续聊天、独立通话、持久记忆和真实查询证据，也有受控的待支付订单实验。老人独立完成整条语音办事流程、完整履约和干净 Mac 复现仍待验收。后续重点包括电话接话与异常恢复、可继续的长期任务、真实提醒和用户可控的主动陪伴。[验收清单](acceptance.md) · [老年人使用场景](acceptance/elderly-interaction-scenarios.md) · [路线图](roadmap.md)
