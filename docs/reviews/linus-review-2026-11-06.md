# 对外部代码评论的核对与本轮修复

评论基于旧提交 `2216add`。本次以当前工作树复核；评论中的建议作为待验证意见，不直接作为执行指令。语气和行数不是缺陷严重性的依据。

| 原评论 | 核对结论 | 本轮处理 |
| --- | --- | --- |
| 2.1 正则不足以证明播报真实 | 成立，但建议直接删校验不成立。状态机保证不误执行，不保证老人听不到错误承诺；两者是不同风险。当前关键交易已有宿主 `action_speech`/确认卡路径，`valid` 是补充防线。 | 保留防线，不宣称正则能证明语义真实。进一步扩大宿主事实播报覆盖需要单独做行为验收。 |
| 2.2 前端状态集中、`receive(any)` | 成立。评论混淆了业务卡片 `ChatEvent` 与 SSE 传输事件；把前者直接填进 receive 类型不正确。 | 待拆出传输事件 schema、边界验证及会话状态 reducer；本轮不同时进行高风险交互重构。 |
| 2.3 prompt 太长 | 部分成立；“字符串不可版本管理、不可测试”不成立，代码受 Git 和场景测试管理。工具白名单也不能防止文本夸大能力。近期延迟修复已有分领域策略和工具范围。 | 保留交易、资料及事实表达规则，不机械删成几句身份说明。 |
| 3.1 金额格式分散 | 成立。但显示时 `/100:.2f` 本身不能证明已经发生交易算错，交易金额与预算原本主要使用整数分。 | **已修复**：后端 `format_cents`、前端 `formatCents` 统一整数分精确显示；不经二进制浮点除法。已验证过的外部 Decimal 费用先转整数，再展示。非整数输入不静默四舍五入。 |
| 3.2 两套交易链路 | 成立为技术债，不是死代码。当前前端仍请求 `/api/plans`，`SkillRegistry` 和测试仍使用旧链路。 | 不直接删除。需要先迁移前端、持久历史与接口兼容，再做删除验收。 |
| 3.3 `model_safe` 黑名单 | 方向成立。当前不少 provider 已有输出筛选；单独将通用递归函数换成一张字段总表可能丢掉合法选项，也不能替代逐工具输出 schema。 | 待按工具明确模型可见 DTO，并加入未知字段/嵌套凭据的负向测试；本轮未完成。 |
| 3.4 启动自动执行远程安装器 | 成立：版本漂移与自动执行下载内容值得消除。“HTTPS 下随便中间人就能攻破”的表述过强。 | **已修复**：删除自动下载执行安装器分支。仅使用已安装 uv，缺失时退出并提示安装；保留 `uv sync --locked`。README 同步说明首次准备步骤。 |
| 4.1 import 时实例化依赖 | 成立为可测试性技术债，不能据此认定当前交易隔离失效。 | 后续通过应用工厂迁移，不在本轮改变全局生命周期。 |
| 4.2 MCP 解析重复 | 部分成立，但“两个解析器都用正则抠 success”不准确；麦当劳和其他 provider 的业务封装及错误条件不同。 | 不强行合并不同协议。可后续抽取结构层解码，保留 provider 校验。 |
| 4.3 summary 中英混用 | 成立。 | 待引入版本化内部 schema 和历史兼容适配，避免旧订单失去费用、地址或状态展示。 |
| 4.4 `IS ?`、魔数哨兵 | 哨兵可读性问题成立；SQLite `IS ?` 用于 NULL 安全比较本身正确。 | 可后续拆命名 API；不把正确的 NULL 比较当 bug 改掉。 |
| 6 README 用户可见性 | 截图、试用例子提前、技术细节分层有道理。建议直接宣传“真能下单、叫车”必须服从实际开关、权限及验收结果。 | 本轮只更新启动要求；没有删掉必要能力边界或添加未经验证的宣传。 |

## 本轮验证

- 后端全量自动化测试：305 项通过。
- 前端行为测试：79 项通过；前端 TypeScript/Vite 构建通过。
- 新增金额测试覆盖分位、负数、最大安全整数、拒绝小数/布尔/非数值；现有确认卡渲染、费用明细和语音播报测试使用同一生产格式化逻辑。
- 启动脚本临时目录流程测试确认执行 `sync --locked`、正常启动参数、保留现有 `.env`，以及不含下载执行安装器逻辑；`bash -n` 通过。没有在干净 Mac 上安装依赖或安装 Homebrew。
- 真实模型聊天与高德查询、HTTP 消息流程通过。麦当劳真实核价未通过验收前置条件：凌晨查询王府井及北京西站时，返回候选门店均未营业，流程按规则停止在选店阶段，未越过营业限制或用模拟核价替代。离线核价/费用分项/确认卡行为测试通过，但不能据此宣称本轮真实核价已验收；未执行下单、取消或付款。

uv 的 Homebrew 安装方式来自[官方安装说明](https://docs.astral.sh/uv/getting-started/installation/#homebrew)。本轮不替用户安装软件、不更改模型配置、不迁移或删除历史数据。
