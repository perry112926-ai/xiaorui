# 任务切换与未支付订单

更新：2026-11-06。

旧购物车、地址草稿、待确认方案、未支付订单不应占据后续对话。新的天气、路线、提醒、资料或闲聊请求按当前意图处理；“继续”“换一份”等简短续问才承接旧候选。切换话题保留可恢复的草稿，同时使旧交易确认失效；用户明确“算了／不点了／这事先不做了”则清除本地草稿并退出流程。真实交易及结果未知的记录保留在本人持久台账，不能因退出聊天被删除、重试或当成已取消。

确认创建成功的点餐、咖啡或叫车方案，会在下一轮释放对应的本地准备上下文，避免已创建订单又被说成购物车尚未下单。新订单状态必须读取官方结果，不能从剩余购物车推断。

“取消订单”先查本人真实订单状态；最近订单为麦当劳时直接读取官方状态。已经取消／关闭／退款／完成时说明实际结果，不重复取消。仍可办理时查询资格和费用，生成独立取消确认；官方没有明确返回可取消及费用时，不擅自调用取消接口，提供官方订单处理渠道，同时允许继续新话题。只有本地草稿时明确说明放弃的是草稿，不声称真实订单取消。

本次只读查询此前真实麦当劳订单，官方返回“已取消”，因此没有再次提交取消。没有推断取消原因或费用。当前仍不能主动到时提醒，老人说“一分钟后提醒我”应直接说明边界并建议手机计时器，不能假装已设置，也不能回复旧点餐流程。

自动化覆盖旧点餐／叫车／咖啡上下文切换、提醒边界、放弃草稿、真实订单已取消、待支付但取消费用未知、创建成功后的上下文释放。真实模型和只读天气接口的隔离 HTTP 验收使用合成购物车，不写商户业务数据：
