# 老人使用高德：场景验收与修复

日期：2026-11-05。范围为 **32 类常见需求、44 轮有效对话结果、13 项真实接口合同检查**，另有故障边界自动化测试。不能将有限用例称为“老人所有可能任务全部通过”。本轮不叫车、不下单、不付款、不联系他人。

证据见[场景与实际返回记录](amap-elderly-2026-11-05.json)。真实文本模型调用官方高德 API；无障碍、逐小时天气等明确不支持的保证由宿主直接解释边界。定位输入用公开北京坐标模拟，家庭资料用公开博物馆地址作虚构占位，均在隔离工作区，不读取或覆盖本人资料。原始记录保留在忽略的 `.local-data/`，公开记录不含 Key、私人地址或订单。

## 发现的问题与修复

1. **明天／后天天气没有能力。** 原来只查 `extensions=base`；增加 `forecast=true` 调用 `extensions=all`，保留日期与报告时间，缺预报不拿实时天气填充。
2. **“最近”没有距离证据。** 增加 `amap_nearby`，用当前已知中心点查询 `/v3/place/around`，按距离排序；显式区分直线距离和实际步行距离。
3. **当前位置没进入高德候选。** 增加 `amap_current_location`，读取 owner 隔离的有效定位，真实逆地理编码后形成起点；无权限触发定位入口，过期不能用于路线／周边。
4. **没有公交数据却补出了线路。** 接入真实公交 API，少步行／少换乘策略可选，不从记忆拼线路。修复公交候选排序、途经站数与乘坐站数的差一，以及同路段备选线路不能算换乘。
5. **解释无障碍限制后仍猜出口。** 明确的无障碍保证请求改由宿主说明无法核实，避免生成虚构站口。精确逐小时天气同样明确不支持，不能补虚构降雨概率。
6. **天气回复容易省略来源时间。** 宿主保留本轮官方报告时间，模型省略时追加，避免把旧报告包装成刚刚测得。
7. **无城市天气追问发生两次150秒模型超时。** 两次异常均保留；首轮无位置的简单指代天气问题改为本机直接澄清。其他云模型请求仍可能超时，这不是对云端稳定性的保证。
8. **“不存在”测试也可能被模糊检索命中。** 初版中文关键词含“测试／公园”触发了不相符候选，不能断言 API 必定零结果。模型语义拒绝与纯任意字符串零结果分开检查；后者还验证旧目的地不会复用。

## 接口与故障验证

最终全量后端自动化测试 **262 项通过**，其中高德专项 16 项，另有宿主来源时间与澄清边界回归。未修改前端；本轮没有把前端构建或真人浏览器测试列为已完成。

13 项真实只读接口检查全部通过：当前天气、带日期预报、真实起点、附近药店／厕所／医院／公园、目的地编码、步行／驾车／公交、真正空结果和空结果后不能复用旧目的地。GPS模拟后的逆地理编码与路线另在多轮场景验证。

自动化故障测试覆盖：缺 Key、官方业务拒绝、HTTP 超时不重试且不回显凭据、缺少／歧义城市、空天气与空预报、无路线、不正确或布尔序号、超范围半径、所有者隔离、定位过期、失败清空旧候选、单位、报告时间、公交排序与站数、宿主能力澄清。测试替身只用于这些故障边界，真实查询没有 mock 回退。

## 仍需现场验收与未支持能力

- 没有验证 Mac 实际定位精度、浏览器权限弹窗、真人语音／方言／回声、老人户外按路线行走或地图 App 跳转。文本与模拟通话上下文测试不能替代这些环节。
- 仍不支持持续位置跟随与偏航重算、保证无障碍／电梯开放、实时公交班次、AQI、精准逐小时降雨、药品库存、医院排队挂号。明确说明限制是通过边界，并非实现了功能。
- 公园内公厕、商场内药店等可能有门票、营业和出入限制，现有 POI 数据不能保证当时可进入。跨城市出行、铁路与所有自然语言表达没有穷尽验收。
- 只复测发生变化或失败的场景，再与完整场景结果合并；不是声称一次无错误跑完。公开 JSON 保留初测失败说明及有效复测来源。
