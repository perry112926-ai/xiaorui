# 老人点麦当劳外卖：场景与验收

更新：2026-11-05。本清单以老人完成一顿饭为单位；代码和离线测试不能替代真实配送验收。

## 当前流程与异常处理

| 场景 | 产品行为 | 验证与边界 |
| --- | --- | --- |
| 不知道吃什么、只说想吃午饭 | 默认一人一份，承接已有预算与用餐偏好；自动选可用门店，最多展示三份有官方图片、默认搭配且整单核价成功的单人套餐 | 真实接口文字与合成语音两轮到最终确认卡片通过；真人体验待验收 |
| 熟悉地址点餐 | 查询账号地址，复述本次收餐地址后选店 | 场景测试；官方地址查询已有真实记录 |
| 临时在新地方 | 本轮定位解析附近地址，再核对实际收餐位置；不沿用家庭或旧城市地址 | 定位隔离、过期及地图查询测试；官方地图真实解析通过 |
| 定位拒绝、失败或不准确 | 可以直接说城市和收餐地址，不把定位作为唯一入口 | 前端定位自动化测试 |
| 地址、电话分几次说 | 保存当前地址草稿，一次追问一个缺项，不重新问已提供信息 | 自动化测试；真实模型三轮草稿到确认卡片通过 |
| 手机号用中文数字、幺或带空格 | 只规范数字读法，复述完整号码核对；掩码、少位、不合法号码要求重说 | 自动化测试；真实模型中文数字输入通过 |
| 换地点或收餐人 | 重置草稿，重新核对门牌和联系方式，不自动拼接旧信息 | 草稿重置测试；是否换地点由对话识别，需真人体验验收 |
| 去酒店前台、公园门口 | 明确填写用户要求的交接位置，不猜房号、不保证骑手送到具体位置 | 草稿“前台”测试；实际交接待配送验收 |
| 新城市、跨城旧地址 | 按本轮明确城市筛选，市名不能来自路名，不默认改成旧地址所在城市 | 南京／广州路名隔离测试；实时服务范围由官方决定 |
| 新增地址 | 卡片显示联系人、手机号、完整地址及发送保存用途，独立“确认新增地址” | HTTP、账号隔离、单次提交、重启未知保护测试；真人地址写入待验收 |
| 闭店或配送范围失效 | 换营业门店、换地址或稍后再查；不能悄悄改成自取 | 场景测试；确认前重新查询配送资格 |
| 没搜到餐品、缺货或套餐选项变化 | 换餐、换店或重新选择，不能编造可售商品 | 实际详情、轮次、旧候选失效测试；官方实时核价失败不下单 |
| 两个人吃、想加个薯条 | 同店购物车分次添加，多次搜餐保留已选餐品；整单核价一次提交 | 自动化测试；真实麦香鱼与薯条购物车、整单及二次核价通过 |
| 少一份、不要刚才那份 | 查看购物车，按当前行修改数量或删除；指代不清时先问 | 更新、删除、空车和失效确认测试；自然指代识别需真人体验 |
| 换门店或配送地址 | 清空原店购物车，重新选餐，旧方案不能执行 | 自动化测试 |
| 套餐还有饮料、配餐没选 | 按官方可用单选搭配准备并在图片和确认卡显示；只有用户要求更换时再改，明确不吃套餐可推荐有图单品 | 默认搭配、单品、换配餐测试；多选轮次排除后再推荐 |
| 不辣、少糖、软一点或有过敏要求 | 仅按真实规格选择；备注说明不保证执行，不以名称推断健康安全 | 对话规则；特殊改配未实现，不能承诺满足吞咽或疾病饮食要求 |
| 明确预算、配送费超过预算 | 整单含费核价；加餐保留已说的预算，准备和确认时均校验，超额停止 | 整单预算及重新核价测试 |
| 需餐具、放前台、无接触配送 | 默认需要餐具，承接用户已说的选择；备注进入订单核对卡，费用以官方返回为准 | 自动化测试；商家实际执行待验收 |
| 说“好的”、重复点确认、旧卡片、处理时改口 | 普通应答不授权；确认绑定具体卡片；重复操作不重复提交，改条件重新核价 | ActionManager、ContactService、HTTP 自动化测试 |
| 未下单说“算了”“不点了” | 放弃本地待确认方案并清空购物车；尚未生成方案也能退出 | 宿主明确口令处理；已创建订单走取消条件查询 |
| 付过了、不会付款、一直未送达 | 查原订单状态，使用原官方支付入口；不因付款不明重建订单 | 订单状态脱敏与确认保护测试；真人付款和配送待验收 |
| 想取消已经创建的订单 | 订单卡片“查看取消条件”；官方明确资格和费用后另行确认 | 麦当劳 HTTP 成功／费用未知测试；实际取消待验收 |
| 下单超时、掉网、重启 | 保留未知记录，先查官方订单，不自动重复交易 | 持久台账及重启测试；真实网络故障下的商户最终状态仍须核查 |
| 已付后改地址、电话、催单、漏餐、退款 | 当前接口没有完整能力时引导官方订单客服；不冒充已修改、已退款或已联系骑手 | 明确的人工接续边界，不作为已实现自动办理功能 |
| 看不清、听不清、说话慢 | 可听播报、打字或单条录音；少量选项、一次一问，确认时清楚读商品、数量、地址和费用 | 现有语音与连续消息测试；真人老人、方言、长停顿及听感待验收 |

真实只读实验的去凭证结果见[本次验收记录](mcd-elderly-live-2026-11-05.json)。

## 复现

```sh
.venv/bin/python -m unittest discover -s tests -q
node --test frontend/tests/*.test.cjs
npm --prefix frontend run build
.venv/bin/python -m experiments.mcd_elderly_acceptance --live
.venv/bin/python -m experiments.mcd_fragmented_acceptance --live
```

两个 `--live` 实验分别调用真实官方查询及真实模型，使用公开地点或虚构联系方式，并通过只读适配器禁止官方写操作。两样餐品实验使用自取核价，以避免未经确认使用真人外送地址；不代表真实外送含费、支付或送达验收通过。完整响应仅保存忽略的 `.local-data/`，不提交地址、电话、凭据或支付链接。

## 本轮通话与支付验收

[脱敏记录](mcd-call-checkout-2026-11-05.json)：真实官方接口与模型、合成语音→真实识别→通话消息→带图候选→选第一份→最终确认卡片通过；文字走同一链路也通过。每次推荐先检查套餐规则和含费总额，选择时重新核价；等候超时、闭店或可售变化时刷新可用图片，不沿用旧报价。实时库存仍可能变化，不能承诺推荐后永远可买。

明确确认后才创建待支付订单，取得有效官方 HTTPS 支付链接后结束通话并在同页打开。重复回执或历史恢复不再次跳转；播报回声与确认词重叠时要求重新确认。以上支付跳转与防重复已有自动化覆盖，本轮没有创建真实订单、打开官方支付页面或执行付款。Mac 锁屏导致实际 Chrome 麦克风验收待继续。

```sh
.venv/bin/python -m experiments.mcd_call_journey --live --delivery --model doubao-seed-2-1-pro-260915
.venv/bin/python -m experiments.mcd_call_journey --live --delivery --text --model doubao-seed-2-1-pro-260915
```

这些实验使用只读适配器，`--model` 仅覆盖隔离实验进程，不修改全局配置；配送实验使用账号中已有地址，不创建地址。完整记录只保存在忽略的本地目录。
