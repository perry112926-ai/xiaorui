# 浏览器定位

需要定位时，宿主会返回 `location_request` 事件，聊天记录显示“授权定位并继续”按钮；历史中曾提示定位的回复也补显按钮。点击后立即请求浏览器定位，成功才发送继续核对的消息，失败保留重试和地标入口。15 秒无回调会停止等待；内嵌浏览器策略禁止或没有权限弹窗时，明确提示在 Safari／Chrome 打开本页及检查系统权限，不将未授权当成已定位。发布后旧页面需刷新以加载新版入口。

网页“＋ → 定位”，或输入／语音说“帮我打车”，会通过浏览器 Geolocation 请求当前位置。须本人授权浏览器与 macOS 定位权限；拒绝、超时、不支持时仍可发送消息并口述地标。不会自动叫车。

原始定位只进入当前会话所有者的内存位置缓存，120 秒过期，服务重启清空；不写个人资料或将位置记为家。请求校验坐标、时间和精度；误差大于 1000 米拒绝使用。浏览器 WGS84 坐标转换为中国地图使用的 GCJ02，模型不自行猜坐标。选定后的地点候选按既有会话机制保存，位置候选带有效期；旧定位不能重新估价或确认叫车。

Agent 工具 `didi_current_location` 读取有效定位，作为起点候选。当前仅允许北京附近范围，边界检查不是行政区精确判定；真实上下车点仍以平台估价返回为准，须向用户核对。当前位置、车型、价格与实际接送点均不构成交易授权，最终确认仍走宿主确认网关。定位更新或清除会废弃旧确认方案。
