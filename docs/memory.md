## 现在能记住什么

重要地址和联系方式由本人或家人在资料卡中核对。普通偏好可以显式修改，也可以从带原话证据的交流中整理。后续对话会查找当前用户和召回代际下的相关片段，证据不足时应询问用户。

## 四层数据

| 层 | 内容与边界 |
|---|---|
| 权威个人资料 | `foundation.sqlite3` 保存当前有效资料、资料版本和遗忘代际。重要字段走人工核对。 |
| 模型会话与证据 | nanobot 保存会话。独立的 `companion.sqlite3` 保存带角色和时间的原话片段、偏好、证据和召回屏障。按 owner 与代际筛选，按词项相关性和预算选择片段。 |
| 页面历史与收件箱 | 恢复消息、卡片、通话摘要与进度。页面历史和模型可召回上下文有各自的范围。 |
| 任务与交易台账 | 保存任务和真实交易结果。恢复记录可用于核查，重启后未知写入保持待核查。 |

## 忘记如何生效

明确的主题遗忘删除匹配的偏好和证据片段，推进后续会话的召回边界，并隔离旧任务召回。未涉及的偏好可迁移到新代际。资料、页面历史、运行时档案、云端处理记录和备份各有自己的保留范围。主题匹配仍有局限，持久删除墓碑也仍待实现。

## 实用性与验收

九轮虚构对话通过了偏好形成、重启召回、主题遗忘与无关偏好保留的检查。LongMemEval-S 完整 500 题的问答结果为 76.8%，基线为 76.0%，跨会话分项为 51.9%。LoCoMo 分层 100 题为 63%，基线为 58%。结果来自指定模型和同模型裁判，完整证据召回和问答是不同指标。协议与限制见[评估记录](evaluations/personal-agent-2026-11-06/results.md)。

## 隐私与隔离

单机资料卡在同一部署内共享。会话、证据召回、任务和操作归属按 owner 区分。提供给模型的资料和检索片段会发送至模型服务，SQLite 和备份按敏感数据保管。运行边界见[部署指南](setup.md#数据备份与访问边界)。

## 复现与实现入口

```sh
uv run --no-sync python -m unittest discover -s tests -p 'test_*memory*.py' -v
```

- [companion_memory.py](../app/companion_memory.py) 保存原话与偏好，执行检索和主题遗忘。
- [agent.py](../app/agent.py) 注入资料和召回证据，管理会话与任务屏障。
- [foundation_store.py](../app/foundation_store.py) 保存结构化资料、会话快照与任务。
- [评估协议](evaluations/personal-agent-2026-11-06/audit.md) 记录真实模型探针与公开数据集复现范围。
